ADR 01
Контекст
	Необходим вариант размещения модели

Решение 
	Из-за небольшоей нагрузки в 35к запросов в месяц (1 запрос в минуту) предлагается вариант гибридный вариант с закрытым контуром

Ограничения 
	Сведения об операциях составляют банковскую тайну, по этому гибридное размещение должно быть соглаосвано со всеми стейкхолдерами процесса (сюда относятся и юристы)

ADR 02
Контекст 
	Стоимость модели
Решение 
	Запускаем в ограниченном сценарии. Пилот на реальных данных в выделенном контуре.
Экономика
	Стоимость владения - расчитано в статье
Эффект
	Рост результативности проверок при том же штате экспертов
Критерии остановки
	Невысокая результативность
	Экономии нет из-за ручного разбора
	Стоимость единицы выше эффекта
Пересмотр
	При росте потока, изменения цен, смене версии модели у вендора, изменение законодательства

ADR 03
Контекст
	Выбор модели для OCR
Кадиндаты
	Tesseract
		+ Open source, бесплатный, локальный
		ограничения: Слабо работает со сложной вёрсткой, таблицами, низким качеством; требует много кастомизации
		вердикт: Baseline / fallback
	PaddleOCR + PP-Structure
		+ Open source, локальное развёртывание, OCR, таблицы, layout, поддержка GPU/ONNX
		Ограничения: Нужна команда для дообучения и эксплуатации
		вердикт: Рекомендованный пилот
Решение
	Пилот: 
		PaddleOCR + PP-Structure + собственный extraction/validation layer.
	Прод: 
		PaddleOCR/PP-Structure в контуре банка + model registry + очередь human-in-the-loop + интеграция с LOS.

ADR 04 
Контекст
	Выбор модели для анализа оттока клиентов банка
Кадидат
	CatBoost
		+ Категориальные признаки из коробки, стабильность
		ограничения: Медленнее, меньше гибкость инфраструктуры
		Вердикт: Challenger
	LightGBM
		+ Высокое качество, скорость, работа с большими объёмами, хорошая калибровка
		ограничения: Требует контроля overfitting
		вердикт: Рекомендованный пилот и прод
Решение: 
	Пилот: LightGBM binary classifier + cost-sensitive threshold + A/B-тест.
	Прод: LightGBM в batch-скоринге + Feature Store + Campaign Management + A/B-платформа.

ADR 05 
Контекст 
	Выбор модели для анализа подозрительных операций
Кадидаты
	Logistic Regression 
		+ Максимальная интерпретируемость, быстрая калибровка
		ограничения: Слабо ловит нелинейные и сетевые паттерны
		вердикт: Baseline, не целевая модель
	Random Forest
		+ Устойчивость, неплохое качество
		ограничения: Хуже масштабируется и интерпретируется, чем бустинг
		вепдикт: Отклонён
	XGBoost
		+ Высокое качество на табличных данных, зрелая экосистема, good SHAP
		ограничения: Требует аккуратной работы с категориями и дисбалансом
		Вердикт: Сильный кандидат
	LightGBM
		+ Высокое качество, быстрое обучение и инференс, хорошо работает на больших объёмах транзакций
		ограничение: Требует контроля переобучения и калибровки
		вердикт: Рекомендованный пилот
Решениие 
	Пилот: LightGBM + rules engine + графовые признаки.
	Прод: LightGBM как основной scorer + детерминированные правила + графовый feature store + human-in-the-loop.
